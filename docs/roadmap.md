# Roadmap

| Milestone | Deliverable | Status |
|---|---|---|
| M0 Setup | Repo layout, docs, templates, CI for tests | done (this commit) |
| M1 Core library | Model, parsers (4 MAT dialects + SGF), rules/legality, canonical hash, XGID/GNUBGID | done; all 14 real files valid |
| M2 Build tool | `bgdb ingest` (inbox to open shard, duplicates, sealing), `bgdb build` (registry, shard summary, manifest, catalog, bgdb-json); deterministic | done; extended with attachments, video links, CC0 and Pages deployment; 150 tests in total |
| M3 Site v0 | Load registry + catalog, list and filter matches, match page | done; checked in a headless browser; illegal plays made in real matches are kept as played; 174 tests |
| M4 Replay v0 | Board, steps, arrows and ghost checkers, position IDs, picture export, menu | done; blue board, plain checkers, Round column; 197 tests; checked in a headless browser |
| M4b XG reader and repair heuristics | Read `.xg` into the logical model (records of 2 560 bytes), tested against the nine text twins; accept fragments that start later, rolls abandoned by the loser, no cascade of start-score errors | done (analysis is detected, not read: M6) |
| M4c Enrichment and splitting | `bgdb enrich` and enrichment through duplicates (overlay applied by the site), sealed shards trusted by a digest (build 5 times faster at small scale), replay data derived in the browser (site 2.4 times smaller), `bgdb verify`, `bgdb split`, `externalShards` and hash files ([growing.md](growing.md)) | done (the data repository's Pages workflow came with decision 0024) |
| Partial matches and damaged files | fragments that start at a score; excerpts with missing games; games kept by their result when the plays are lost; the `Illegal play (...)` marker read as a position; `V-DAMAGED` for missing plays ([partial-matches.md](partial-matches.md), [decision 0020](decisions/0020-excerpts-lost-games-and-missing-plays.md)) | done. Still to do: `partial` flag in the catalog and `has:partial`, a hash per game to supersede fragments |
| Quality ingest of an archive | A dry run over 3 144 tournament files: more exporters' layouts read, typos corrected only when a single legal play fits, `Set Pos` checked, files that are not UTF-8, `bgdb ingest --salvage` (decision 0021) | done; 342 tests; 53 files of that collection stay refused, with their reasons |
| Event and round of an archive | Headers cleaned at ingest (placeholders out, event from a `Site` that names a server and an event), ratings split from names, a warning for matches the list cannot tell apart, `bgdb meta` (review sheet of what file names propose, written to the sidecars), corrections of event, round and date as enrichments applied by the site (decision 0022) | done. Still to do: the Contribute page does not show or edit event and round yet (CTB-13 "correct it inline") |
| Transcriptions of one match | Copies recognised by their rolls (95% in common, same players and length), the better one kept by the ingest (`superseded`), ties left to the review sheet (`near-duplicate`, `reject` in the column `action`); tabs in move rows read at 8-column stops (decision 0023) | done |
| Games from a set position | A game that starts from a position given by the file (`; Set Pos=` in XG text exports: an opening that was not recorded). The position is checked and refused today. To build: the game's start position in the model, the identity, the normalised `.mat`, the replay data and the board. Fixture `fixtures/invalid/set-position-start_11pt.mat`; the tests marked `todo` in `packages/core/test/set-position.test.js` and `packages/cli/test/replay.test.js` must pass. Seen in 9 of 3 144 tournament files | proposed |
| Data repositories | Tools and site in `bgdb`, data in a series of data repositories, one current; `sources.json` merged by the site; shard numbers continued; warning and stop by size, `new-data-repo` and `switch-data-repo` run by the maintainer; reusable workflows pinned to a tag; shards sealed at 5 000 matches; a build cache keyed by content hash ([decision 0024](decisions/0024-data-repositories.md)) | done: `sources.json` (the site reads several data repositories), global shard numbers (`firstShard`), the size limits (`repoPolicy`: warning, stop, an issue), a `closed` repository, shards sealed at 5 000 matches, the build cache (a second build of 95 matches: 0.2 s instead of 8 to 11 s), reusable workflows and `templates/data-repo/`, `new-data-repo`, `publish-data-repo` and `switch-data-repo`; `data/` moved out of `bgdb`. `bgdb-data-1` is live (tools `v12`) |
| M5 Contribution loop | shared check (`analyzeGroup`), `bgdb review`, bot comment, verdicts and auto-merge decision, four workflows, issue path, Contribute page (browser check, ZIP, upload page) | done; the workflows (now reusable, called by each data repository) run on GitHub for `bgdb-data-1`: a pull request, a fork, or a ZIP dropped into a "Submit a match" issue ([contributing-flow.md](contributing-flow.md)) |
| Player names (decision 0025) | Real names over the board, pseudonyms online. Pseudonyms before anything is sent: a names key per contributor (made and kept by the browser, a copy to download), HMAC names stable for one key, both sides renamed; platform, time of day, event, round, ratings and remarks removed; `.mat` normalised, `.sgf` and `.xg` rewritten and read back | done: the Contribute page (pseudonyms, and a box for a match played over the board, sent with its real names and `"origin": "otb"`), `V-HANDLE` and `V-ORIGIN` in the review and the ingest of a data repository (`"names": "pseudonyms"`), `bgdb erase` with `data/erased.tsv` (`V-ERASED`) and a "Remove a match" issue form, the `by:` search (catalog version 3), `bgdb hide-names --key-file` for pull requests by hand. Still open: the answers of the platforms' forums |
| Contribute page and guide | The Contribute page as numbered steps (a GitHub account first), with pictures of GitHub; `guide.html` shows the same steps before starting (`site/js/steps.js`, pictures in `site/img/guide`) | done; the pictures were taken again on 2026-10-08 on `bgdb-data-1` (made-up names, the bot's last answer included) |
| M6 After MVP | Text index and type-ahead, caching, opening and position indexes, analysis display, XG importer | |
| M7 Open up | Public repo, licence decision, 200-500 rights-cleared seed matches | |

Possible side tracks: `bgdb import` for more formats (FIBS, Snowie text, GamesGrid), reading the analysis inside `.xg` files
