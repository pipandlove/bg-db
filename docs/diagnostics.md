# Diagnostics: codes, causes and fixes

`bgdb check` and `bgdb ingest` report problems with a **code**, a plain sentence, a location (file line, game, move) and often a
"how to fix" hint. Severities: **error** (the match is refused), **warning** (accepted, flagged), **info** (advisory).
Codes are stable (spec VA-02); the JSON output of `bgdb check --json` carries them.

| Code | Severity | Typical message | Cause and fix |
|---|---|---|---|
| `V-FORMAT` | error | "Cannot understand this line", "Cannot understand the move", "No game found", "Match length line not found", "this eXtreme Gammon file was saved in the middle of a game" | The text is not a supported match format, or is cut or edited. Check the line named; for an `.xg` that cannot be read, export a text file from eXtreme Gammon. See [formats](formats/README.md). |
| `V-LEGAL` | error | "the move ... cannot be played from this position", "is not legal for this roll", "no move written but a legal move exists" | A checker is missing or a target point is blocked, or the play ignores the rule to use as many dice as possible (and the larger die). The first illegal move is named: usually a transcription error. If the play really was made in the match, declare it (`V-ILLEGAL` above). |
| `V-DAMAGED` | error | "Game 1, move 27: the play of X for 24 is missing (3 different plays were possible): the position is unknown from here" / "the play of X for 64 is hidden ... but the game goes on" / "This match is damaged: plays are missing in 6 of 6 game(s)" | A roll written with no play although a play was possible, not at the end of a settled game, or a hidden play (`???`, `Illegal play` without a dump) followed by more moves. With `--salvage` the game can be kept by its result (decision 0021). The position is unknown, the match cannot be rebuilt: `check` prints `DAMAGED`, the file stays in the inbox. A wrong play is `V-LEGAL`, not this. See [decision 0020](decisions/0020-excerpts-lost-games-and-missing-plays.md). |
| `V-TURN` | error | "the same player rolls twice in a row" | A turn is missing or a column was misread. |
| `V-CUBE` | error | "a double was offered but nobody took or dropped", "the player does not own the cube", "doubling is not allowed in the Crawford game", "the cube goes from 2 to 8" | The cube sequence is inconsistent with the rules. |
| `V-CUBE` | warning | "cube above the limit" | The file's cube limit is exceeded. |
| `V-SCORE` | error | "starts at 2-0 but the previous games add up to ...", "does not reach a result", "the file says N points but the moves give M", "the file says player X wins but the moves show Y" | Scores or results in the file disagree with the replay. Check the "Wins N point" lines, gammons and the cube value. A start score that does not follow from the previous `Wins` line names that line ("the Wins line of game 3 says X wins 2 point(s)"): the `Wins` line is never overridden, so the file was probably edited or cut. |
| `V-SCORE` | warning | "the file says the match ends with game N, but the score is a-b in an L-point match" | **Ledger.** A last game whose `Wins` line says "and the match" when the score has not reached the match length. See [game endings](game-endings.md). |
| `V-SCORE` | warning | "the site records 4 points for a resignation, which is impossible with the cube at 1 (at most 3); counted as 3, the most possible: the real value is unknown", "a resignation worth N point(s) does not fit the cube value", "the match is unfinished", "no declared result" | Plausibility problems that do not block ingestion. |
| `V-SCORE` | info | "the site counts N point(s) (capped at the match length)" | Normal for OpenGammon and Foxamon (the points the winner needs) and for some tournament exports (the match length): the last game is capped. |
| `V-RESULT` | info | "Game 3, move 40: X rolled 64 and played only 22/16, and the game stops there: counted as a resignation (Y wins)" / "rolled 16 and played nothing" | **Tail.** The last roll of a game that a `Wins` line settles is only a part of a legal play (one die, or none). Kept as written, not part of the identity. See [game endings](game-endings.md). Anywhere else, or without a `Wins` line, it is a `V-LEGAL` error. |
| `V-RESULT` | warning | "Game 3, move 40: the last roll of X (64: 22/15) is not a possible play: it is ignored, and the game is counted as a resignation as the file says" | **Tail.** The last roll of a settled game holds moves that cannot be played. They are dropped (data is lost, hence a warning); the roll is kept without moves. |
| `V-RESULT` | info | "nothing was rolled by X and the file says that player wins: the Wins line is followed" / "the double was not answered; counted as a drop" / "no points are written for the resignation; N taken from the score at the start of game G" | The `Wins` line settles what the slot (`00:`, an unanswered double) does not say; the score of the next game fills in the points only when there is no `Wins` line. |
| `V-RESULT` | warning / info | "ends without a bear-off or drop; it is treated as a resignation by X" | The game stops with checkers left and no resignation marker. Info for eXtreme Gammon text and BackgammonGalaxy (they never write one), warning elsewhere. |
| `V-RESULT` | info | "the site records 2008 points for a resignation; counted as 2, which the winner needed to win the match" | A resignation marker larger than possible, cut to what the winner needed (see [formats](formats/README.md)). |
| `V-PARTIAL` | warning | "The file starts with the score already at 8-4 in a 17-point match: only part of the match is recorded" | **Repair.** The first game of the file has a score already: the match is a fragment. It is accepted and its result is counted from that score (the result carries `partial.startScore`). Not applied to money games, to a start score at or above the match length, nor to a gap between two games of the file. |
| `V-PARTIAL` | info | "a player is one point from winning and nobody doubles: taken as the Crawford game" / "... and the cube is used: taken as a game after the Crawford game" | A fragment that starts with a player at match point: the file does not say whether the Crawford game was played. A double proves it was; with no double the Crawford game is the better guess (SGF files carry the flag, which is kept). |
| `V-PARTIAL` | warning | "Game 3 starts at 8-10 but game 2 ended at 6-7 (the Wins line of game 2 says X wins 2 point(s)): games are missing between them, the file is an excerpt" | **Excerpt.** The start score only moves forward and stays below the match length: games are missing, the start score is trusted ([decision 0020](decisions/0020-excerpts-lost-games-and-missing-plays.md)). A score that goes backwards is a `V-SCORE` error. |
| `V-PARTIAL` | warning | "Game 13: the first play is not written and the position the source gives after it is far from the opening position (the plays before it are lost); only its result is kept (X wins 2 point(s))" | **Lost game.** Kept by its declared result; the result is part of the identity. |
| `V-FORMAT` | error | "the file starts the game from a set position (\"Set Pos\", line 18)", "sets a position that the moves before do not lead to" | XG's `; Set Pos=` gives a position the moves do not lead to: a game from a set position is not supported yet (roadmap) and is never replayed from the opening. With `--salvage` the game can be kept by its result. |
| `V-FORMAT` | info | "The file is not UTF-8: it was read as Windows-1252 (Western European)" | An older Windows export; the names are read right and stored as UTF-8. Nothing to do. |
| `V-RESULT` | info | "the last play of X (44) is not written and the file says that player wins: the roll bears off every checker left, so it is read as the final bear-off", "the Wins cell is on the row of the last bear-off, in the other column; the bear-off decides the winner" | Older transcriptions ([game endings](game-endings.md)). Nothing to do. |
| `V-PARTIAL` | warning | "Game 6: the moves cannot be read (V-LEGAL line 149: ...); the result is confirmed by the score of game 7; only its result is kept" / "...; the game is left out" / "the file stops in the middle of this game ...: the game is left out" | **Salvage** (`--salvage`, decision 0021): the match is kept with that game by its result, or without it. Without `--salvage` the same file is refused with the original errors. |
| `V-META` | warning | "A player name is missing", "Both players have the same name", "The tag ... was ignored", "the key ... is not used", "\"round\" was ignored", "Nothing tells it apart from 0001/... in the list (same players, date, event, round and length)" | Metadata problem; the match is still accepted. For a look-alike, give its round in its `.bgdb.json` (`bgdb meta` proposes it from the file names), or once stored `bgdb enrich <id> --round ...` ([decision 0022](decisions/0022-event-round-from-headers-and-file-names.md)). |
| `V-COPY` | warning / info | "Another transcription of this match is X (98.9% of the rolls in common; first difference: ...), and nothing tells which one is right", "It is another transcription of 0001/... (valid only by salvage), which stays in the database", "The event \"...\" was taken from another transcription of this match" | Two files of one match ([decision 0023](decisions/0023-transcriptions-of-one-match.md)). Choose in the review sheet (`reject` in the column `action`), or keep both. |
| `V-META` | info | "The event \"Online match\" says nothing about the match: it was left out", "The round \"Round 0\" ...", "The event \"...\" was taken from the Site tag" | The headers were cleaned automatically (decision 0022). |
| `V-LINK` | warning | "A video link was ignored: only https links are accepted", "only YouTube links are accepted (not ...)", "does not point to a single YouTube video" | The link was dropped; the match is accepted. Use `https://youtu.be/<id>` or `https://www.youtube.com/watch?v=<id>`. |
| `V-ATTACH` | warning | "X.sgf does not describe the same match as the text file", "could not be read", "is not an eXtreme Gammon file", "the SGF and the text disagree on the points of game N" | The attachment was skipped (or, for a points disagreement, kept and reported). Check that both files come from the same match. |
| `V-FILE` | warning | "X is N KB, above the limit of M KB: it was not kept" | An attachment is larger than `sealPolicy.maxAttachmentKB`. |
| `V-ILLEGAL` | warning | "Game 6, move 19: X played 11: 3/2 1/off(2), which is not a legal play; accepted as played because the source says it was made" | The match really contained this illegal play and the source declared it. It is kept and flagged. See [formats](formats/README.md#illegal-plays-made-in-real-matches). |
| `V-ILLEGAL` | warning | "Game 12, move 10: the play of X (11) is not written; the position the source gives after it cannot be reached by a legal play: accepted as played, reconstructed as 11: 14/10 11/10(2)" | **Marker.** An `Illegal play (...)` gives the position after the play ([format](formats/illegal-play-marker.md)). The position is exact, the moves are one way to reach it. Info instead of warning when a legal play reaches it. |
| `V-ILLEGAL` | warning / info | "the source declares an illegal play in game G, move M, but no such play was found" (warning); "the source says ... was illegal, but it is a legal play; treated as legal" (info) | A declaration that does not match the transcription: check the game and row numbers. |
| `V-RIGHTS` | error | "The rights box of the form is not ticked" | An issue of the "Submit a match" form without the rights box ticked (`bgdb from-issue`). |
| `V-CLOSED` | error | "This data repository is closed: it takes no more matches" | An issue sent to a closed data repository (`bgdb from-issue`, decision 0024): send the match again from the Contribute page. |
| `V-INTERNAL` | error | "The normalised file does not read back to the same match" | Raised by `ingest` if the writer could not reproduce a match. This is a bug: please keep the file and report it. |

**One error is reported once.** When a game cannot be replayed, the running score still follows the points the file declares for it, so later games do not report a wrong start score as well.

Codes planned by the specification but not produced yet: `V-NAMES` (player alias hints),
`V-DUP` (duplicate hints in the browser), `V-SIZE`, `V-ANALYSIS` (see spec section 10.4).
